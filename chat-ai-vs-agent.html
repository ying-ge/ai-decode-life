AI Agent 实践课程 · 第一讲

聊天式 AI
与 AI Agent

从“回答问题”到“完成任务”

你问 → 它答 vs 你给目标 → 它去做

一句话区别：谁来决定“下一步”

聊天式 AI 的每一步由你推动；Agent 的下一步由它自己判断。

聊天式 AI

一问一答

你提问→AI 回答→你再提问…
  • 输出的是文字、代码、建议
  • 执行、验证、纠错都由你来做
  • 每次对话结束，任务不会自己继续
AI Agent

目标驱动的循环

你给目标→规划 · 行动 · 检查→交付结果
  • 能调用工具：运行代码、读写文件、上网检索
  • 根据执行结果自行调整，直到完成或求助
  • 交付的是完成的任务，不只是一段回答

用实验室来类比

同样是“帮你分析数据”，角色完全不同。

聊天式 AI ≈ 电话咨询的专家

你描述问题，专家在电话里告诉你该怎么做。

  • 看不到你的电脑和数据
  • 操作要你自己动手
  • 跑出错误，你再打一次电话

知识很强，但手不在现场

AI Agent ≈ 坐在你工位的研究助理

你交代目标，助理自己查资料、跑分析、改错。

  • 能打开文件、运行程序
  • 遇到报错先自己排查
  • 做完向你汇报，关键处请你拍板

有手有脚，但仍需你把关

Agent 是怎么工作的

在大模型之外，多了工具、记忆和一个能反复执行的循环。

大模型负责理解目标、做判断的“大脑”
工具搜索、运行代码、读写文件、调用数据库或 API
记忆对话上下文，加上可保存、可检索的文件与笔记
循环控制决定何时继续、何时停止、何时请你确认

并排对比

两者用的往往是同一类大模型，差别在“外面搭了什么”。

聊天式 AIAI Agent
交互方式你问一句，它答一句你给目标，它多步自主推进
能做什么生成文本、代码、解释还能执行：跑代码、改文件、查数据
谁决定下一步你Agent（关键节点由你确认）
出错时你发现并反馈先自查自改，仍卡住再求助
典型风险答案不准，但影响停在屏幕上错误会被执行出去，影响真实文件和数据

同一个任务，两种做法

任务：“分析这批 RNA-seq 数据，找出处理组与对照组的差异基因。”

聊天式 AI
你描述数据格式和需求
AI给出一段 R / Python 代码
你复制到本地运行
你报错后把信息贴回去，反复修改
AI Agent
读取自己打开表达矩阵和分组表
编写并运行差异分析代码
排错报错后自行查看并修复
出图汇总火山图、富集结果、报告
你检查结果并确认
需要人参与的步骤两种方式都离不开人，区别是人要做多少事、在哪里介入

能做事，也意味着更需要小心

用 Agent 的基本原则：让人始终在回路里。

会出错幻觉和中间步骤的小错误会层层累积，结果看起来合理但可能是错的
权限与安全能执行就可能误删文件、泄露数据，只给完成任务所需的最小权限
成本与耗时多步循环会消耗更多调用次数和时间，不是所有问题都值得用 Agent
可复现与责任过程要留记录；科研结论由你负责，关键结果必须自己复核

小结与讨论

聊天式 AI 回答你的问题；AI Agent 替你完成任务，但仍需要你把关。

1. 在你的生物学学习或实验中，哪些任务适合交给 Agent？
2. 哪些步骤必须由人来判断，为什么？
3. 如果 Agent 给出的分析结果和你的预期不一致，你会怎样验证？
